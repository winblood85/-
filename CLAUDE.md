# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## Язык общения

Общайся с владельцем репозитория на русском. Объясняй просто: владелец только начинает программировать.

## Секреты и пароли — главное правило

Владелец репозитория **не должен передавать тебе пароли, токены, API-ключи, коды 2FA/SMS, приватные ключи, cookies сессий и другие секреты** — ни в чате, ни на скриншотах, ни в файлах.

### Когда нужно предупредить

Если задача выглядит так, будто для неё нужен секрет, или владелец собирается его показать, — **остановись и предупреди до того, как он это сделает**. Примеры:

- задаче нужен доступ к внешнему сервису (бот, API, база данных, платёжка, почта, маркетплейс);
- владелец спрашивает «какой пароль/токен тебе прислать?» или собирается вставить ключ в чат;
- нужно войти в личный кабинет какого-либо сервиса;
- владелец присылает скриншот, где может быть виден токен, пароль, ключ или QR-код для входа;
- в присланном тексте, файле, логе или скриншоте ты заметил секрет.

### Как предупреждать

1. Коротко и заметно: **«⚠️ Не присылай мне пароль/токен — это небезопасно.»**
2. Объясни почему: всё, что попадает в чат, видно мне и сохраняется в истории разговора.
3. Дай конкретный правильный путь (см. ниже) с пошаговыми действиями.
4. Продолжай ту часть работы, которая не зависит от секрета.

### Если секрет уже попал в чат или в репозиторий

- Не используй и не повторяй его в ответах, коде, коммитах или логах.
- Сразу скажи владельцу, что секрет нужно **немедленно сменить/отозвать** в сервисе, где он выпущен, и объясни, где это сделать.
- Если секрет попал в git — удаления файла недостаточно: он остаётся в истории, поэтому главное — отозвать ключ.

### Правильные пути вместо передачи секрета

- **Код** читает секреты только из переменных окружения (`os.environ[...]`, `process.env...`). Никогда не записывай значения секретов в код, коммиты, README или тесты.
- **Локально**: владелец сам вписывает значения в файл `.env` (он в `.gitignore`). Ты поддерживаешь актуальный шаблон `.env.example` с именами переменных, но без значений.
- **GitHub Actions**: владелец добавляет значение в *Settings → Secrets and variables → Actions*; в workflow используется `${{ secrets.ИМЯ }}`.
- **Если секрет нужен тебе в облачной сессии**: владелец добавляет его в настройки окружения (меню окружения в заголовке сессии → Edit → переменные окружения). Честно предупреди, что такой секрет тебе будет доступен, поэтому туда кладётся только отдельный токен с минимальными правами — никогда не личный пароль.
- **Вместо пароля — токен**: предлагай выпустить отдельный API-токен с минимальными правами (по возможности только чтение), сроком действия и возможностью отзыва; для разработки — тестовый/sandbox-ключ.
- **Доступ к сервисам**: предпочитай OAuth/коннекторы, где пароль тебе не передаётся.
- **Вход в личный кабинет**: ты туда не входишь. Объясни владельцу, что нажать самому, и попроси скриншот без чувствительных данных.
- **Скриншоты**: напоминай замазывать токены, ключи, номера карт и личные данные перед отправкой.

### Защита в репозитории

- `.gitignore` блокирует `.env`, ключи и файлы с учётными данными — не ослабляй эти правила.
- Workflow `Secret scan` (gitleaks) проверяет каждый push и PR; включена GitHub Push protection.
- Ветка `main` защищена: изменения только через Pull Request.
